# 워크플로우 버전 (Workflow Versions)

**File → Save As New Version**(`Option/Alt` + `Shift` + `S`)은 열려 있는 파일을 덮어쓰는 대신 워크플로우의 현재 상태를 새 파일에 작성하고 해당 새 파일의 편집 상태로 전환합니다. 다시 저장하면 또 다른 새 파일이 생성됩니다. 각 저장은 시퀀스의 다음 파일을 생성하여 이전의 모든 버전을 디스크에 그대로 유지합니다.

## 생성되는 결과물 (What it produces)

버전이 지정된 저장은 워크플로우의 파일 이름에 패딩된 `_v<number>` 접미사를 추가합니다. `my_workflow.py`를 이 방식으로 저장하면 `my_workflow_v001.py`가 생성되고 그 다음 `my_workflow_v002.py`가 생성되는 식입니다. 버전 번호는 항상 증가하며 기존 버전 파일을 덮어쓰지 않습니다.

## 사용하는 경우 (When to use it)

위험한 구조 변경 전, 워크플로우를 전달하기 전, 또는 반복 작업에 따라 스냅샷 기록을 유지하고 싶을 때와 같이 현재 진행 상황을 잃지 않고 되돌아갈 수 있는 체크포인트가 필요할 때 Save As New Version을 사용하세요. 각 버전은 자체 파일이므로 이전 버전으로 돌아가는 것은 해당 파일을 열기만 하면 됩니다.

## Save 및 Save As와의 차이점

- **Save**는 현재 열려 있는 파일을 덮어씁니다. 새 파일이 생성되지 않습니다.
- **Save As**는 *사용자*가 선택한 이름으로 새로운 별도의 파일을 작성하고 해당 파일 편집으로 전환하는 일회성 복사본입니다.
- **Save As New Version**도 새 파일을 작성하지만 이름이 자동으로 선택되며(시퀀스의 다음 번호) 반복 사용되도록 설계되었습니다. 해당 파일에서 이후 저장할 때마다 동일한 시퀀스가 계속 증가합니다.

자동 저장을 사용 설정하면 **Save**처럼 동작합니다. 일정한 간격으로 현재 열려 있는 파일을 자동으로 덮어쓰며 자체적으로 버전이 지정된 파일을 생성하지 않습니다. 구성 방법은 [자동 저장](editor/running_workflows.md#자동-저장-auto-save)을 참조하세요.

!!! note "엔진 또는 라이브러리 버전 고정과의 차이점"

    워크플로우 버전은 워크플로우 *파일*의 번호가 매겨진 복사본일 뿐이며 프로젝트가 올바르게 실행되는 데 필요한 엔진 또는 라이브러리 *버전*과는 관련이 없습니다. 프로젝트를 정상 작동이 확인된 엔진 버전이나 특정 라이브러리 버전 세트에 고정하려는 경우 [엔진 및 라이브러리 버전 고정](projects/version_pinning.md)을 참조하세요.
